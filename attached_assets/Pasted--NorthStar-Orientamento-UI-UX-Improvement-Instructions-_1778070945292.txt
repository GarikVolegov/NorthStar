## 2. 📐 Scala tipografica standardizzata

**Problema:** Heading e body text usano classi `text-xl`, `text-2xl`, `text-lg` sparsi senza gerarchia coerente.

**Istruzione per l’agente:**

Aggiungi al `tailwind.config` (o al CSS globale se si usa Tailwind v4 con `@theme`) una type scale semantica:

```css
@layer base {
  h1 { @apply text-4xl font-bold tracking-tight leading-tight; }
  h2 { @apply text-2xl font-semibold tracking-tight leading-snug; }
  h3 { @apply text-xl font-semibold leading-snug; }
  h4 { @apply text-base font-semibold leading-normal; }
  p  { @apply text-base leading-relaxed text-[var(--color-text-secondary)]; }
  small { @apply text-sm leading-normal text-[var(--color-text-muted)]; }
}
```

Applica queste classi semantiche in tutte le pagine: landing, risultati, settore, news, dashboard, roadmap. Rimuovi qualsiasi `font-bold` / `text-2xl` applicato inline che duplica queste regole.

## 3. 🧩 Skeleton Loader unificato

**Problema:** `UserDashboard` usa skeleton per le professioni, mentre altre sezioni (news, roadmap, wiki) usano spinner o placeholder diversi.

**Istruzione per l’agente:**

Crea un componente riusabile `artifacts/orientamento/src/components/ui/Skeleton.tsx`:

```tsx
import { cn } from "@/lib/utils";

interface SkeletonProps {
  className?: string;
  lines?: number;
  variant?: "text" | "card" | "avatar" | "badge";
}

export function Skeleton({ className, lines = 1, variant = "text" }: SkeletonProps) {
  const base = "animate-pulse rounded bg-gray-100";

  if (variant === "card") {
    return (
      <div className={cn("rounded-xl border border-gray-100 p-5 space-y-3", className)}>
        <div className={cn(base, "h-5 w-2/3")} />
        <div className={cn(base, "h-3 w-full")} />
        <div className={cn(base, "h-3 w-4/5")} />
      </div>
    );
  }

  if (variant === "avatar") {
    return <div className={cn(base, "h-10 w-10 rounded-full", className)} />;
  }

  if (variant === "badge") {
    return <div className={cn(base, "h-5 w-16 rounded-full", className)} />;
  }

  return (
    <div className={cn("space-y-2", className)}>
      {Array.from({ length: lines }).map((_, i) => (
        <div key={i} className={cn(base, "h-3", i === lines - 1 ? "w-3/5" : "w-full")} />
      ))}
    </div>
  );
}
```

Sostituisci tutti i loading state esistenti nel progetto con questo componente. Usa `variant="card"` per news e professions, `variant="text"` per descrizioni.

## 4. 🔴 Pagina Risultati — Gerarchia visiva

**Problema:** `/risultati/:id` mostra troppe informazioni sullo stesso livello visivo: RIASEC, Bussola Interiore, top 3 settori, AI analysis, professions, upsell. L’utente non sa dove guardare.

**Istruzione per l’agente:**

Ristruttura il layout della pagina `risultati.tsx` in tre sezioni visivamente distinte con separatori chiari:

**Sezione 1 — Hero (above the fold):**

- Nome utente + frase personalizzata basata su `dominantSpirit`
- Top sector match in evidenza (card grande con match score animato 0→XX%)
- CTA primaria: “Esplora questo settore →”

**Sezione 2 — Il tuo profilo (scroll):**

- RIASEC profile chart (Recharts radar o bar)
- Bussola Interiore: 5 spirit bar in una card separata con sfondo leggermente colorato per distinguerla visivamente dal RIASEC

**Sezione 3 — Altre direzioni:**

- Settore #2 e #3 come card più piccole (secondary style)
- Se loggato: AI professions section con `Skeleton variant="card"` durante il caricamento
- Se non loggato: singolo banner “Salva i tuoi risultati” con CTA registrazione

Aggiungi `position: sticky` alla top section con il match score principale in modo che rimanga visibile durante lo scroll.

## 7. ⚡ Streaming SSE — Loading states coerenti

**Problema:** Le tre feature SSE (Wiki AI, Roadmap, Grafo RAG) hanno probabilmente UI di loading differenti.

**Istruzione per l’agente:**

Crea un hook riusabile `artifacts/orientamento/src/hooks/useSSEStream.ts` che gestisce:

- stato `isStreaming: boolean`
- stato `content: string` (aggiornato in streaming)
- stato `error: string | null`
- cleanup dell’EventSource al unmount

E un componente `StreamingIndicator.tsx`:

```tsx
export function StreamingIndicator({ isStreaming }: { isStreaming: boolean }) {
  if (!isStreaming) return null;
  return (
    <div className="flex items-center gap-2 text-sm text-muted">
      <span className="flex gap-0.5">
        {[0, 1, 2].map(i => (
          <span
            key={i}
            className="h-1.5 w-1.5 rounded-full bg-brand animate-bounce"
            style={{ animationDelay: `${i * 0.15}s` }}
          />
        ))}
      </span>
      <span>Sto elaborando...</span>
    </div>
  );
}
```

Usa `useSSEStream` + `StreamingIndicator` in `wiki.tsx`, `roadmap.tsx` e `grafo-conoscenza.tsx` per uniformare l’esperienza.

## 9. 🔒 Premium Badge — Pattern coerente

**Problema:** Quattro sistemi di indicatori numerici diversi (confidence score, matchScore, fitScore, spirit bars) usano stili e nomi diversi per concetti simili (rilevanza personalizzata).

**Istruzione per l’agente:**

Crea un componente `MatchBadge.tsx` riusabile:

```tsx
interface MatchBadgeProps {
  score: number; // 0–100
  label?: string;
  size?: "sm" | "md";
}

export function MatchBadge({ score, label = "Match", size = "md" }: MatchBadgeProps) {
  const color =
    score >= 80 ? "bg-green-50 text-green-700 border-green-200" :
    score >= 60 ? "bg-brand-light text-brand border-brand/20" :
                  "bg-gray-50 text-gray-600 border-gray-200";

  return (
    <span className={`inline-flex items-center gap-1 rounded-full border px-2 py-0.5 font-medium ${color} ${size === "sm" ? "text-xs" : "text-sm"}`}>
      {label} {score}%
    </span>
  );
}
```

Usa `<MatchBadge score={matchScore} label="Match" />` nei settori,  
`<MatchBadge score={fitScore} label="Fit" />` nella roadmap,  
`<MatchBadge score={confidence * 100} label="Score" />` nell’admin review.

## 10. 🧭 Navigazione — Pattern unico

**Problema:** L’admin review usa sidebar navigation, il resto dell’app usa (presumibilmente) top navbar. Due pattern strutturali diversi nella stessa codebase.

**Istruzione per l’agente:**

Mantieni la sidebar nell’admin (è un backoffice e ha senso lì), ma assicurati che:

1. La top navbar dell’app principale abbia sempre visibili: Logo | Test | Dashboard | News | Premium — con highlight attivo sulla route corrente (usando `useLocation` di Wouter).
1. Nelle pagine premium (`/wiki/:id`, `/roadmap/:id`, `/grafo`) aggiungi un breadcrumb coerente:
   
   ```
   Dashboard → [Nome Settore] → Wiki AI
   ```
1. Il link “← Torna alla Dashboard” sia sempre presente come prima voce del breadcrumb, non nascosto in fondo alla pagina.
