Ho letto in dettaglio replit.md, .replit e package.json. Ecco un’analisi completa dei problemi che causano il fallimento del deploy su altri account.

🔴 Problemi Critici (causano il deploy rotto)
1. Nessun build e run command nella sezione [deployment]
Il blocco [deployment] nel .replit contiene solo:

router = "application"
deploymentTarget = "autoscale"
[deployment.postBuild]
args = ["pnpm", "store", "prune"]


Il postBuild fa solo pnpm store prune (pulizia cache), non compila nulla. Replit Autoscale ha bisogno di:

[deployment]
build = ["pnpm", "run", "build"]
run = ["node", "artifacts/api-server/dist/index.js"]


Senza questi, il deploy non sa come costruire né come avviare l’app in produzione.

2. Frontend in modalità dev anche in produzione
Il workflow usa sempre run dev:

args = "PORT=8081 BASE_PATH=/ pnpm --filter @workspace/orientamento run dev"


In deployment, Vite dev server non dovrebbe girare. Serve prima vite build e poi servire la dist con Express o un server statico. Su altri account questo crea problemi di performance e spesso crash per memoria.

3. Python 3.12 chiamato ma il modulo installato è 3.11

modules = ["nodejs-20", "web", "python-3.11"]   # modulo installato
# ...
args = "cd artifacts/ai-agents && python3.12 -m uvicorn ..."  # chiamata


python3.12 non è disponibile se il modulo è python-3.11. Il servizio Python AI crasha all’avvio su qualsiasi altro account che fa un fresh setup. Fix: uniformare a python3.11 nel workflow o cambiare il modulo a python-3.12.

4. AI Integrations (OpenAI) funzionano solo sull’account originale

AI_INTEGRATIONS_OPENAI_BASE_URL
AI_INTEGRATIONS_OPENAI_API_KEY


Queste variabili sono iniettate automaticamente da Replit solo sull’account del proprietario che ha attivato l’integrazione. Su qualsiasi altro account che forka o importa il repo, queste non esistono → tutte le funzionalità AI (Wiki, Roadmap, Grafo RAG) falliscono silenziosamente o con 500.

5. JWT Secret salvato su filesystem locale — incompatibile con Autoscale
Da replit.md:
artifacts/api-server/src/lib/auth-jwt.ts ora salva il secret in artifacts/api-server/.local/.jwt-secret
Replit Autoscale usa istanze effimere: ogni replica ha un filesystem separato e i file non persistono tra restart. Questo significa:
	•	Il JWT secret cambia ad ogni restart/replica → tutti gli utenti vengono disconnessi
	•	Su altri account il file potrebbe non essere scrivibile → crash al bootstrap
Fix: usare esclusivamente la env JWT_SECRET da Replit Secrets, con fallback solo in dev.

6. DATABASE_URL, STRIPE_SECRET_KEY, GNEWS_API_KEY, TAVILY_API_KEY sono account-specifici
Questi sono segreti Replit che esistono solo nell’account originale. Su altri account il server si avvia ma:
	•	Il DB non è raggiungibile → crash immediato al seed
	•	Stripe non funziona → checkout rotto
	•	News e Research scheduler falliscono
Il codice deve gestire gracefully l’assenza di queste variabili (log warning invece di crash), e il README deve documentare le env richieste.

🟡 Problema di Sicurezza Grave
7. ADMIN_KEY hardcoded nel .replit pubblico su GitHub

[userenv.shared]
ADMIN_KEY = "f62cf4651857423a20c21453538232bd"


Questo file è pubblicamente visibile su GitHub. Chiunque può accedere alle route /admin/* e all’Admin Review Dashboard. Va rimosso dal file e spostato in Replit Secrets (che non vengono committati).

🟠 Problemi Strutturali
8. Nessun start script di produzione sul pacchetto api-server
Il package.json root ha solo build e typecheck. Non c’è un comando start che compili TypeScript e avvii il server compilato con node dist/index.js. In dev funziona con tsx o ts-node, ma in produzione serve il codice compilato.
9. pnpm-lock.yaml può causare conflitti su versioni diverse di pnpm
Il lockfile è generato con una versione specifica di pnpm. Se l’ambiente Replit dell’altro account ha una versione diversa, pnpm install può fallire o installare dipendenze errate.
Fix: aggiungere nel .npmrc:

engine-strict=true


E specificare in package.json:

"engines": { "pnpm": ">=9.0.0" }
